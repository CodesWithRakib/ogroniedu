## 1. Feature Status Classification Definitions

- `COMPLETED_VERIFIED`: Full-stack implemented, database backed, permissions enforced, unit/integration tested, and browser verified.
- `VERIFICATION_PENDING`: Implemented end-to-end, awaiting automated browser/E2E verification pass.
- `PARTIALLY_IMPLEMENTED`: Core functionality exists, but secondary actions or edge-case handling are incomplete.
- `FRONTEND_ONLY`: UI page/component exists, but lacks real backend API integration.
- `BACKEND_ONLY`: API endpoints and DB entities exist, but user interface is missing or stubbed.
- `INTEGRATION_MISSING`: Both frontend and backend exist, but API contract mismatch prevents complete workflow.
- `BUGGY`: Implemented but contains verified defects or UI rendering anomalies.
- `BLOCKED`: Blocked by external third-party dependency (e.g. live production gateway credentials).
- `NOT_IMPLEMENTED`: Defined in specifications, but neither code nor endpoints exist.
