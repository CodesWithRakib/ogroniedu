# Refactoring Backlog (Phase 22) — dependency-ordered, with acceptance criteria

## B — Backend modularization

- **DI rule (round 4, load-bearing):** every constructor-injected service MUST use an explicit `@Inject(X)` (or `@Inject(forwardRef(...))` for genuine module cycles). Bare `private readonly x: XService` params resolve under `tsc` (decorator metadata) but are `undefined` under tsx/esbuild, which does not emit `design:paramtypes` — this broke application boot after the B-5 splits (`LearningAccessService`, `LedgerService`, `PaymentsService` tokens) while all 409 unit tests still passed (manual construction bypasses DI). Fixed by adding explicit `@Inject` in the four admin sub-services; verified by a real `NestFactory` boot. Madge full-app scan: only benign entity cycles + the pre-existing `notification.service ↔ notification.gateway` cycle remain.
- **Runtime validation caveat (round 4):** for the same metadata reason, the global `ValidationPipe` silently skips DTO validation under tsx. New boundary code (e.g. `SupportService`) re-validates required fields in the service so malformed bodies fail fast with 400 + `details[]` on every runtime. A platform-wide fix (explicit validation or ESM dist repair) is tracked below.
- **Deploy packaging (round 4, pre-existing breakage found live):** `pnpm start` (`node dist/main.js`) fails with `ERR_MODULE_NOT_FOUND` (tsc emits extensionless relative imports; no ESM resolution). Docker `CMD ["node", "apps/api/dist/main.js"]` is affected. Recommend fixing the ESM dist (module nodenext + `.js` import extensions, or tsx-based runtime) before the next release. Also: `db:migrate` reads `packages/database/dist/migrations` — **always rebuild `@ogroniedu/database` after adding a migration**, otherwise new files are silently skipped as "up to date" (this hid `012_support_tickets.sql` until rebuilt).
